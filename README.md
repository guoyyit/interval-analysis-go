# ivanalyze — 整数区间静态分析服务

对指定目录/包下的 Go 源码做批量**区间抽象解释**（interval abstract
interpretation），在每个函数的控制流图（CFG）上迭代传播整数变量的取值
范围，报告三类潜在运行时缺陷：

- 除数为零（`/`、`%=` 等）
- 数组/切片/字符串下标可能越界
- 整数运算与转换可能溢出

分析结合**控制流 + 数据流**：条件分支会对区间做约束求精，循环在循环头
做加宽（widening）保证有限收敛，并在收敛后做有限次收窄（narrowing）恢复
精度。它不是对单个表达式的局部判断。

## 快速开始

```bash
# 分析单个包目录
go run ./cmd/ivanalyze ./path/to/pkg

# 递归分析整个模块的子目录，8 路并发，只看 high
go run ./cmd/ivanalyze -recursive -jobs 8 -min-severity high ./internal/...

# 结构化 JSON
go run ./cmd/ivanalyze -json ./pkg > report.json

# 30 秒超时；增量缓存
go run ./cmd/ivanalyze -timeout 30s -cache .ivcache.json ./pkg
```

退出码：`0` 正常（可能仍有告警）；`2` 参数错误；`3` 分析不完整（超时/取消）
——**不完整结果绝不会以退出码 0 冒充“无缺陷”结论**。

## 抽象域

`domain.Interval` 是闭区间 `[Lo, Hi]`，端点用 `math/big.Int` 精确表示，
外加一个 `Empty`（不可达）标记。这样一个域统一覆盖有符号/无符号、
8/16/32/64 位整型，运算中间结果不会因宿主机器字宽而提前溢出。

每个具体整数类型由 `domain.Bounds{Min, Max}` 描述（`IntBounds(bits, signed)`）。

- **未知值 = 全区间**。函数参数、外部读取、包级变量以及任何无法证明取值
  的表达式，一律取该类型的全区间 `TypeTop(bounds)`，不做未证明的假设。
- **交 / 并**：`Intersect` 与区间壳 `Union`（join）。
- **关系痕迹**：区间无法表达“去掉一个内点”（如 `x != 0` 后 `x` 仍是全
  区间）。域额外带一个 `NonZero` 布尔事实，由分支求精设置、在状态拷贝/
  合并/运算中传播，使 `if d != 0 { .../d }` 这类常见守护能被精确识别。
- **局部数组**：对由复合字面量构造的局部数组维护常量下标元素区间；非常量
  下标读取时对所有可能元素求并。外部/切片/map 不跟踪，读取保守取全区间。

算术（`Add/Sub/Mul/Neg/Div/Mod`）先做**精确**区间运算：

- 精确结果完全落在类型边界内 → 返回精确区间，`overflow=false`；
- 一旦精确结果可能超出边界 → 结果退化为该类型全区间并置 `overflow=true`，
  从而对 Go 的模回绕语义保持保守；
- `Div/Mod` 的除数区间含 0（且无 `NonZero` 事实）→ 置“可能除零”；
  `MinInt / -1` 单独识别为溢出。

## 收敛策略

1. 为函数构建 CFG，识别**回边目标**（前驱索引 ≥ 自身）为循环头。
2. 在循环头做经典**区间加宽**：新状态某端点越过旧端点时，直接推到类型
   边界。这保证迭代在有限步内稳定（区间关于每个类型边界高度有限）。
3. 到达不动点后做 `NarrowingPasses` 次**收窄**：只把曾被推到类型边界的端
   点用后继的精确端点收紧。收窄结果仍是后不动点，因此**只会减少假阳性，
   不会重新引入被排除的真实错误**。
4. 若迭代超过 `MaxIterations` 仍未稳定，函数被标记 `incomplete`，其结果不
   作为安全结论参与判定。

**非关系区间域的固有不精确**：像 `for i:=0;i<N;i++{ s += a[i] }` 中 `s`
的上界依赖循环执行次数（一种关系不变量）。纯区间域在加宽后可能把 `s`
推到类型上界从而保守地报告 `s` 累加可能溢出——这是**可能的真错误方向**
（域不会把出错判成安全），但属于已知的精度上限。要消除它需要关系域（如
八边形/差分约束），本工具选择保持域简单且保守。

## 保守性承诺（soundness）

> 凡被判定为**安全**（未报警）的运算，在该函数任何可达输入下都不会触发
> 对应运行时错误。

保证手段：

- 未知值一律全区间；外部调用、channel、反射、`go/defer`、`select` 等无法
  建模的构造按“所有目标可达 / 结果全区间”处理，只可能多报，不会漏路径。
- 溢出即退化为全区间，覆盖模回绕的所有可能值。
- 收窄只允许“从类型边界向内收紧”，永不扩张。
- 摘要以**全区间参数**计算，对所有输入成立；调用点使用其返回区间壳。
- 递归函数组迭代到摘要稳定；无法稳定或超预算则标记不完整。

代价是**可能存在假阳性**（保守告警）；工具的目标是零漏报而非零误报。

## 配置（精度/性能，均不放宽保守性）

| 参数 | 含义 |
| --- | --- |
| `-max-iterations` | 每函数不动点迭代步数上限；超限标记不完整 |
| `-narrowing` | 加宽后收窄次数；越多越精确（可能越少告警），越慢 |
| `-min-severity` | `low`/`medium`/`high` 输出过滤 |
| `-jobs` | 并行分析函数数；`1` 为串行，结果与任意并发度逐条一致 |
| `-timeout` | 总超时；到点取消并标记未完成 |
| `-tests` | 包含 `_test.go` |
| `-recursive` | 递归子目录 |
| `-cache` | 持久化函数摘要文件，用于跨进程增量复用 |

这些参数只改变**告警数量与耗时**，不改变“安全即不会出错”的语义。

## 告警语义

每条 `Alert` 含：源文件 `file/line/column`（及 `position` 字符串）、函数
与包、缺陷类型、严重程度、人类可读的**触发条件简化描述** `condition`、
**区间依据** `interval_basis`（涉及变量区间与类型范围）、以及说明。

- 同一 `(位置, 缺陷类型)` 在一个函数内只报告一次（去重）。
- 报告按严重程度（高→低）再按位置稳定排序，保证串行/并发输出完全一致。
- 严重程度默认：除零、越界为 `high`（必 panic）；溢出为 `medium`（静默回绕）。
- JSON 结构见 `report.Alert` / `report.Report`。

## 函数摘要与增量分析

`analyzer.Summary` 是函数的可靠过近似：各整数返回值的区间、`MayPanic`、
同包被调函数依赖 `Deps` 及每个被调者摘要的指纹 `DepsSummaries`、源码
`Hash` 与自身 `Fingerprint`。

- 函数体及其**所有依赖摘要指纹**都未变时，直接复用缓存结果。
- 任一被调者摘要变化，依赖方的 `DepsSummaries` 不再匹配 → 自动重新分析。
- 持久化缓存仅在**整次分析完整**时写入；不完整分析产生的缓存不会被当作
  完整结果复用。
- `SummaryStore` 的读写全部加锁；`Get` 返回拷贝，杜绝并行任务间的就地
  修改竞争。

## 并发与取消

- 按调用依赖 DAG **分层**：同层互不依赖的函数并行分析，下一层等上一层摘要
  提交后再开始；相互递归的函数成组迭代到稳定。
- 共享缓存仅通过带锁的 `SummaryStore` 访问，因此并发安全，且结果与串行
  逐字节一致（测试 `TestConcurrentConsistency` 以告警多重集断言）。
- 全程透传 `context.Context`：超时或收到 SIGINT/SIGTERM 时，未完成的函数/
  包标记 `incomplete`/`canceled`，顶层 `Report.Incomplete=true`，CLI 退出码
  为 3。

## 测试

```bash
go test ./...
```

覆盖：

- 循环加宽有限收敛（`domain` + analyzer 端到端）
- 跨函数摘要参与调用点计算（常量返回不报警 / 全区间返回报警）
- 增量复用与依赖失效（被调者指纹变化触发重分析）
- 并发一致性（`-jobs 1` 与 `-jobs 16` 告警多重集相同）
- 超时/取消（取消后所有函数标记不完整，绝不输出完整结论）

## 包结构

- `domain` — 区间抽象域（算术、交并、加宽/收窄、比较求精、`NonZero`）
- `cfg` — 由 AST 构建带条件边的 CFG
- `analyzer` — 状态、表达式/语句迁移、分支求精、摘要、不动点引擎、调度
- `loader` — 基于 `go/packages` 的类型检查加载与源码哈希
- `report` — 告警结构、去重/排序/过滤、文本与 JSON 渲染
- `config` — 精度/性能配置与校验
- `cmd/ivanalyze` — 批量分析命令行入口
