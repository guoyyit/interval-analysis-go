# interval-analysis-go

针对 Go 源码的**数值区间静态分析服务**。对指定目录下的包做批量分析，
在控制流图（CFG）上执行整数变量取值范围的区间抽象解释，报告三类潜在
运行时错误：

- 除数为零（`div_by_zero`）
- 数组 / 切片索引可能越界（`index_out_of_bounds`）
- 整数运算可能溢出（`integer_overflow`）

分析结合了控制流与数据流：条件分支会对区间进行精化，循环通过不动点迭代
传播，而不是对单个表达式做局部判断。

## 快速开始

```bash
# 分析单个包（目录）
go run ./cmd/analyzer -dir ./path/to/pkg

# 递归分析目录下所有包，文本输出，8 个并发 worker
go run ./cmd/analyzer -dir ./src -recursive -workers 8 -format text

# 精度/性能参数
go run ./cmd/analyzer -dir ./src \
  -max-iterations 200 \
  -widen-after 3 \
  -narrowing-passes 3 \
  -timeout 30s \
  -min-severity medium
```

也可以作为库使用：

```go
a := intervalanalysis.NewAnalyzer(intervalanalysis.DefaultConfig())
result, err := a.Analyze(context.Background(), "./src", true)
_ = intervalanalysis.WriteJSON(os.Stdout, result)
```

## 抽象域

数值抽象元素是闭区间 `[Lo, Hi]`（`int64` 表示），加上最大元 `top`，
`top` 表示对应整数类型的完整取值范围：

- 支持 `int/int8/.../uint64/uintptr/byte/rune`；
- `Join` 为逐点最小上界；
- 状态格 `State` 是“变量 → 区间”的点积映射；未绑定的整型变量默认取其
  类型全区间；
- 另维护一张“数组/切片对象 → 已知长度区间”的长度表，用于越界判定。

算术语义对加、减、乘、除、取模按区间端点给出保守结果；当任意一对端点
组合可能超出类型可表示范围时，结果上近似为全区间并产生溢出告警。
除零、`MinInt/-1` 溢出、无符号回绕均被显式建模。

分支条件（`< <= > >= == !=` 以及 `&&`、`||`、`!`）会对状态做条件
精化，条件不可满足时该后继为不可达（bottom）。

## 控制流与收敛

1. 为每个函数构建 CFG，支持 `if`、`for`（含 `init/post` 与
   `break/continue`）、`range`、`switch`（含 `fallthrough`）、
   `type switch`、`select`、`goto` 与带标签语句、带标签
   `break/continue`、提前 `return` 等结构；无法精确处理的结构按保守
   方式连接，不丢路径。`break` 在 `switch`/`select` case 内表示跳出
   该 `switch`/`select`；回退 `goto` 构成回边，与循环回边一样触发加宽，
   保证收敛。
2. 在 CFG 上做工作集混沌迭代，直到状态不动点。
3. 仅在**循环回边**（含回退 `goto`）上、经过 `WidenAfter` 轮普通迭代后
   进行区间加宽（widen 到最近阈值或无穷），保证含循环函数有限步收敛。
4. 达到加宽不动点后执行有界次数的**收窄 / 精度提升**
   （`NarrowingPasses`，`0` 表示默认值）。收窄把每个块的入状态与**所有
   入边状态的 Join** 求交——只在已验证的后不动点上做，只会缩小区间、
   不会增加错误的“安全”结论；逐条边分别求交是不保守的，本实现不做。

### 汇合点的赋值语义

状态格 `State` 中**未绑定的整型变量即 top**（其类型的完整取值范围）。
在控制流汇合点（`if`/`switch`/`for` 及嵌套结构的合并处、跳转语句的
目标处），对每个变量取所有可达前驱路径的最小上界：

- 变量在**所有**前驱上都有绑定 → 绑定区间的逐点 Join；
- 变量只在**部分**前驱上有绑定 → 与另一侧的隐式 top  Join，结果为
  top（即不绑定）。因此“只在某条分支 / 某个 case 中赋值”的包级变量，
  在汇合后按全区间处理：作为除数会报告 `div_by_zero`，作为下标会报告
  `index_out_of_bounds`，参与可能溢出的运算会报告 `integer_overflow`；
- 仅在部分路径上成立的精化事实（如分支条件带来的区间收缩）不会被
  带到汇合点之后。

加宽同样遵守该约定：对一侧未绑定的变量，加宽结果保持 top，绝不退回
较窄区间。

终止性由 `MaxIterations` 硬上限保证；达到上限或上下文取消时，函数标记为
未完成，绝不把未收敛结果当作完整结论。

## 保守性承诺

凡是被判定为安全的运算，在任何可达具体输入下都不会触发对应错误：

- 函数参数、外部读取、解析不了的来源一律按**全区间**处理，不做任何
  未经证明的假设；
- 外部函数 / 函数值调用的整型结果按全区间处理；
- 地址被取用、作为参数传递给调用或属于包级全局的变量，在调用点被
  保守地置为未知（havoc）——包括条件表达式中的调用；
- 汇合点只对“所有前驱路径都成立”的事实保持精化，部分路径上的赋值
  在汇合后按 top 处理（见上节）；
- `goto`、标签、`fallthrough`、带标签 `break/continue` 构成的每条
  可达路径都进入 CFG，不会被静默跳过；
- 赋值左侧、自增自减、`send`、`go`/`defer`、调用参数中的下标与除法
  表达式同样参与检查；
- 加宽是上界算子，收窄只在已验证的后不动点上、与所有入边的 Join
  求交；
- 配置（迭代上限、加宽阈值轮数、精度提升次数、worker 数）只影响
  告警数量与耗时，**永远不会放宽安全判定**：在所有配置都收敛的前提
  下，同一输入的真实可达错误不会从告警集合中消失。

代价是可能存在误报（false positives），但设计目标是**不漏报**
真实错误。

## 函数摘要与增量分析

- 每个函数生成摘要：在“所有整型参数为全区间”的前提下得到的整型返回值
  区间、函数体内告警、源码哈希与完成标志。因此摘要覆盖任意具体调用，
  跨函数调用以返回值区间参与计算。
- `SummaryStore` 是并发安全的缓存，并维护 调用方 → 被调方 的反向依赖。
- 增量分析：重新运行时，源码哈希未变的函数直接复用摘要；某函数变化时，
  其全部传递依赖方通过反向索引失效并重新分析。
- 递归 SCC 作为整体做有界摘要不动点迭代，循环内调用先取全区间的
  保守初值，再迭代精化。

## 并发与一致性

- 调用图做 SCC 缩点后按依赖层级调度；同一层互不依赖的 SCC 可并行，
  worker 数量由 `Workers` 配置。
- 所有共享状态只通过加锁的 `SummaryStore` 读写。
- 告警在汇总阶段统一去重、按 `(文件, 偏移, 类别, 函数)` 稳定排序，
  因此并发结果与串行执行**逐条一致**。

## 未完成判定与退出状态

支持 `context.Context` 取消与 `Timeout` 配置。满足以下任一条件时，相应
函数或包被**显式列为未完成**（`unfinished`），结果 `complete=false`：

- CFG 不动点迭代达到 `MaxIterations` 上限仍未收敛（迭代预算耗尽）；
- 递归 SCC 的摘要不动点在预算内未稳定；
- 分析被 `Timeout` 或上下文取消打断（含加载阶段中断）。

只有在**所有目标函数都达到保守定点**时才报告 `complete=true`。
命令行退出状态与结论可信度一致（`ExitCode`）：`complete=true` 退出
`0`，否则退出非零（`2`）；加载/参数错误退出 `1`。告警数量不影响退出
状态。任何不完整结果都不会以“零告警的完整结论”形式输出：未完成的
函数会出现在 `unfinished` 中，且已发现的部分告警仍会保留在报告里。

## 告警语义

每条告警包含：类别、严重程度、源文件行列、所属函数、简化触发条件与
区间依据（evidence）。同一处缺陷（相同位置 + 类别 + 函数）只报告一次。

| 类别 | 默认严重程度 | 触发条件（简化） |
| --- | --- | --- |
| `div_by_zero` | high | 除数区间可能包含 0 |
| `index_out_of_bounds` | high | 索引区间可能落在 `[0, len-1]` 之外 |
| `integer_overflow` | medium | 运算可能超出该整数类型表示范围 |

可用 `-min-severity low|medium|high` 过滤，输出默认按严重程度信息与位置
稳定排序。

## 结构化输出

JSON 报告形如：

```json
{
  "complete": true,
  "unfinished": [],
  "warnings": [
    {
      "category": "div_by_zero",
      "severity": "high",
      "file": "/path/to/x.go",
      "line": 12,
      "column": 13,
      "offset": 234,
      "function": "pkg.Func",
      "message": "divisor may be zero",
      "evidence": "divisor range [-inf,+inf] may contain 0"
    }
  ]
}
```

## 测试

```bash
go test ./...
go test -race ./...
```

测试覆盖：区间算术与边界、循环收敛、条件数据流、跨函数摘要、
增量复用与依赖失效、串行/并发一致性、超时中断与严重程度过滤，以及：

- **汇合点语义**（`merge_test.go`）：包级整型变量只在部分分支 / case /
  循环迭代中赋值时，汇合后作为除数与下标必须告警；所有路径都赋值时
  汇合保持精确、不误报；
- **跳转路径**（`goto_test.go`）：`goto` 跳过赋值、回退 `goto` 成环、
  `fallthrough` 链、循环内 `switch` 的 `break`、带标签
  `break/continue` 构造的路径上的越界与除零；
- **一致性与守恒性**（`consistency_test.go`）：同一输入在串行与多并发
  下告警逐条一致；无循环输入在不同迭代上限 / 加宽轮数 / 收窄次数下
  告警集合完全相等，含循环输入的真实错误告警在所有收敛配置下守恒；
  收窄（含经摘要返回值影响调用方的路径）不会丢真实告警；迭代预算
  耗尽时结果为未完成、列出 `unfinished` 且退出码非零
  （`ExitCode` 约定）。
